# Замена и доработка экранов

В Hunter preview есть два самостоятельных оформления — Classic R2 и Hunter
Reference. Их виджеты используют общую телеметрию и модель компоновки.
Настройки экранов меняются без перепрошивки; новый тип графического компонента
или драйвер датчика добавляется в C и требует новой сборки.

| Изменение | Где выполнить |
|---|---|
| Стиль, тема, название и показ заголовка | Дисплей / телефон; произвольный текст — телефон |
| Порядок, копирование, добавление, скрытие, удаление | Телефон / JSON |
| Основные метрики горизонтального свайпа | Телефон / JSON; отдельные диапазоны, единицы, пороги |
| Положение и размер виджета | Сенсорный drag/редактор, мышь Windows, canvas телефона, точные поля |
| Сетка, сохранение, отмена, сброс одного экрана | Дисплей / телефон |
| Тип, цвет, шрифт, единицы, предупреждения | Общий профиль; телефон даёт произвольный RGB/текст |
| Однотонный/встроенный фон, затемнение, масштаб | Дисплей/телефон/JSON по доступным полям |
| Загрузка собственного фонового изображения | Телефон,4ресурса RGB565; нужна новая таблица Flash |
| Калибровки ДМРВ/лямбды, таблицы, источник | Телефон / JSON, общие расчёты с прошивкой |
| Новый вид шкалы, системная страница, графический ресурс | `ui_core`, `ui_widgets`, новая сборка |
| Новый физический датчик | Адаптер `sources`, регистрация/проверки; затем сопоставление метрики |

## Что показывает предпросмотр телефона

Canvas использует те же координаты, типы виджетов и JSON-поля. Он рисует дуги,
цифровые блоки, заголовок и фон, позволяет перетаскивать и изменять размер за
нижний правый угол, сообщает о границе круга и перекрытиях. Это приближённый
предпросмотр: браузерный шрифт и рисование не идентичны LVGL. Точный результат
нужно смотреть в настоящем Windows Simulator или на приборе.

Правки остаются в редакторе до «Сохранить». Импорт JSON сначала загружается
в редактор; окончательный C-validator прибора отклоняет невалидный профиль
целиком. Движения не пишутся во Flash. Export/import не включают пароль AP,
сырые диагностические журналы и бинарные изображения.

## Границы конфигурации

`version:4 / layout.version:2`. Старые `3/1` автоматически переносятся в Classic
без замены геометрии. До8приборов,8виджетов и8пресетов на прибор; системные
страницы не занимают квоту. До20метрик UI и73функции каталога с указанием
доступности. Будущие TPMS/парктроники/сервисные команды не выданы за драйверы.
ID —15ASCIIбайт; заголовок —63UTF-8байта; единицы —15UTF-8байт.
Геометрия480×480 ограничена кругом232px; всё проверяется общей C-функцией.

Полный профиль помещается в отдельном `ui_profiles` NVS64KiB. OTA на старой
таблице сохраняет совместимый режим до6144байт packed-профиля; более сложный
профиль требует [миграции таблицы](../hunter-background-migration.md).

Смена style сохраняет текущую компоновку. Кнопка «заводской вид Reference»
явно применяет стандартную Reference-композицию. Для сохранения двух своих
вариантов используйте копирование экрана или отдельные JSON-профили.
Клавиши1/2 симулятора выбирают заводские наборы Classic/Reference: перед такой
сменой сохраните собственный вариант в отдельный JSON.
