# Пошаговая инструкция: от закупки до первого запуска

Это руководство разделяет **доступные сейчас** действия и то, что будет доступно после разработки полного `firmware.bin`. По состоянию R0 есть инженерная документация, концепт корпуса и работающий HTML-макет, **но нет готовой прошивки БК для ESP32-S3**.

## 0. Что заказать

См. [BOM](BOM.md). Минимальный стенд: Waveshare ESP32-S3-Touch-LCD-2.1 (480×480), согласователь K-Line L9637D (либо отдельная чужая PCB из [REFERENCES](REFERENCES.md) с тщательной проверкой), 4-pin SH1.0 провод, защищённый БП 12→5 В, провода, держатель предохранителя 1 A, простая колодка для разъединения. Для собственного компактного варианта — уровень TX из SN74AHCT1G125 и делитель RX. Заказывать Gerber без ревью нельзя.

## 1. Проверить будущий интерфейс прямо сейчас — без автомобиля

1. Открыть файл [ui/index.html](../ui/index.html) в браузере Windows (в GitHub: Raw/Download; либо скачать репозиторий ZIP через кнопку Code → Download ZIP).
2. На макете нажать «Двигатель», «Обороты», «Поездка», «Диагностика», «Меню», «Настройки», «Wi-Fi».
3. Переключить тему и яркость; проверить свайпы на сенсорном устройстве.
4. На странице Wi-Fi увидеть **демо** QR. Он кодирует несуществующую сеть BK-MIKAS-DEMO. Не пытаться использовать для реального подключения к БК.

## 2. Отдельно включить физический дисплей

1. Не подключать пока K-Line и автомобильные провода.
2. Питать Waveshare через **native USB-C** от исправного 5-В источника согласно документации платы.
3. Скачать и запустить официальный пример от Waveshare (ссылка ниже), убедиться, что сенсор, яркость и RGB изображение работают. Не начинать с неизвестной чужой прошивки.
4. Зафиксировать конкретную ревизию 2.1 или 2.1B, порты и версию ESP-IDF.
5. Проверить входы/выходы 4-pin UART на лабораторном макете (без K-Line) и особенности переключения USB-UART.

Waveshare: https://docs.waveshare.com/ESP32-S3-Touch-LCD-2.1

## 3. Собрать интерфейс K-Line

В [WIRING.md](WIRING.md) есть распиновка L9637D, цепь питания, логический делитель и направления UART. Сверить SOIC-8 **сверху**, pin 1 по точке/ключу корпуса. К машине до тестов не подключать.

| Наша новая жила | Откуда | Куда |
|---|---|---|
| Жёлтая (цвет **нашего** провода) | диагностика K-Line, УАЗ разъём №11 | L9637D K pin6 |
| Чёрная | диагностика масса, УАЗ разъём №12 | GND схемы |
| Красная | +12 после включения зажигания, через предохранитель | питание 12_PROTECTED → DC/DC и VS pin7 |
| Голубая, внутри корпуса | Waveshare GPIO43 TXD | буфер → L9637D TX pin4 |
| Зелёная, внутри корпуса | L9637D RX pin1 | делитель → Waveshare GPIO44 RXD |

Цвета — лишь для **нового жгута БК**; к цветам проводов штатного УАЗа не привязаны. Диагностический pin 2 = постоянный +12 В, в R0 **не подключаем**, чтобы прибор не оставался постоянно запитан. Нельзя физически разрывать K-Line ЭБУ ↔ диагностическая колодка.

## 4. Испытать адаптер на столе

Мультиметр: на входе ~12 В, после DC/DC стабильно 5 В, на UART RX GPIO44 не более 3,3 В, TX ESP32 никогда не соединён напрямую с 12 В; проверить отсутствие замыканий. Потом лабораторный K-Line-имитатор и логи. Включить реальный БК к ЭБУ можно только когда **написана и испытана** специальная прошивка Микас.

## 5. Что потребуется, чтобы прошить готовый БК

После появления проверенной сборки нужны будут файл `firmware.bin`, таблица разделов/адресов ESP-IDF и подписанная инструкция для данной ревизии Waveshare. Тогда будет единый комплект: прошить из Windows через native USB, включить зажигание, дождаться проверки паспорта ЭБУ, выбрать первый экран, затем открыть Wi-Fi и сканировать реальный QR. Пока файлов сборки нет, команды прошивки не приводятся как будто они уже работают.

## 6. Когда появится телефонная панель

1. Экран БК → Меню → Wi-Fi → Включить локальную сеть.
2. Получить динамические SSID/пароль и реальный QR.
3. На телефоне подключиться к созданной сети 2,4 ГГц; интернет не требуется.
4. Открыть `http://192.168.4.1`, посмотреть параметры и логи.
5. Выключить Wi-Fi — прибор продолжит читать Микас по проводу.

Эти действия описывают **проектируемый пользовательский сценарий** и будут проверяться отдельно после реализации ESP-IDF SoftAP и веб-сервера.
