# Прошивка R2: сборка и границы проверки

Цель — ESP32-S3, ESP-IDF **5.5.1**, LVGL **9.6.0**. Точные версии
приведены для воспроизведения сборки; фактический результат см. в `docs/R2_STATUS.md`.

## Windows 10

Установите [официальный ESP-IDF Tools Installer](https://docs.espressif.com/projects/esp-idf/en/v5.5.1/esp32s3/get-started/windows-setup.html),
выберите IDF 5.5.1. В ESP-IDF PowerShell:

```powershell
cd C:\projects\bk-mikas-7.2\firmware
idf.py set-target esp32s3
idf.py menuconfig
idf.py build
idf.py -p COM5 flash monitor
```

`COM5` заменяется фактическим портом. **Перед прошивкой снять JP1 интерфейса R2**.
Переключатель UART Waveshare перевести для USB-UART по официальной инструкции;
для работы диагностической линии вернуть внешние GPIO43/44. Питание USB и
внешние 5 В одновременно допускается только после подтверждения развязки питания.
GPIO19 занят TX_ARM: native USB D−/D+ не подключать. Основная и вторичная USB Serial/JTAG console ESP-IDF отключены,
чтобы загрузочные сообщения приложения не шли на диагностический UART.
USB-UART физически разделяется переключателем и сервисной перемычкой;
загрузчик ROM не контролируется настройкой console приложения.

K-Line и Wi-Fi по умолчанию выключены: `BK Mikas R2` в menuconfig.
K-Line включать после проверки R2, подтяжек, перемычек и безопасного ARM
при сбросе/BOOT/пропадании питания. Проверка на машине не проводилась.
Если отсутствует display driver, приложение продолжает запуск без экрана;
наличие собранного binary само по себе не подтверждает работу LCD.

## Обмен

Перенос выполнен из собственного `uaz-mikas-diagnostics`, commit
`1e0ab5f22677e76904540b23176dce46d37a34b5`, `diagnostics/protocol.py`,
`mikas_profile.py`, `kkline_web.py`. Транспорт **9600 8N1**, monitor **0B**,
не стандартные OBD-II PID. Инициализация — read-only запрос `01`, ожидается
один байт `0B`. Применять ISO9141 fast/5-baud init наугад нельзя.

Кадр: тело + дополнение суммы до нуля; `0D` кодируется `40 CD`, `40`
кодируется `40 00`; завершающий `0D`. Приём сравнивает эхо полностью,
проверяет экранирование, сумму, размер ответа; неверные кадры отбрасываются.
После трёх секунд без валидных значений сбрасывается состояние связи,
затем повторяется запрос версии. Один worker владеет UART, UI и HTTP получают
снимок через mutex; сетевые запросы не выполняют обмен с ЭБУ.

Команды разрешены только `01`, `02`, `51..58` и `61 PID`. Команды `62`,
сброс ошибок, вентилятор, форсунки, EEPROM отсутствуют в API.
Ошибки читаются раз в 10 секунд (`02`), формат count + пары code/flags.
Скорость, пробег, остаток топлива и л/100 км без независимого источника
не вычисляются. Лямбда показывается как raw, расход воздуха — «нужны данные»
до подтверждения коэффициента. Декодеры не являются верификацией датчиков.

## Настройки и телефон

NVS хранит версионированные настройки, проверяет диапазоны и избегает записи
одинаковых значений. Повреждение NVS не вызывает автоматического стирания.
При включённом Wi-Fi создаётся WPA2 SoftAP с уникальным случайным паролем
(128 бит, хранится в NVS), максимум два клиента. Пароль не пишется в Git или
логи. Экран Wi-Fi получает реальные SSID/пароль для QR. Адрес телефона:
`http://192.168.4.1/`, JSON: `/api/telemetry`. Защита доступа сейчас — пароль
WPA2; все подключённые клиенты имеют read-only доступ к телеметрии.
Редактор конфигураций по HTTP и OTA ещё не реализованы.

## Проверки без устройства

```bash
bash tools/test_firmware_host.sh
```

Тесты проверяют исходный формат monitor, escaping всех 256 значений,
плохие checksum/escape/размеры, запрет записи, возраст данных и формулы.
Используются AddressSanitizer/UBSan. Симулятор и UI описаны в `simulator/README.md`.
Для лога сборки PowerShell: `idf.py build 2>&1 | Tee-Object build-log.txt`.
Логи перед отправкой проверить на персональные данные.

Остаётся проверить UART на стенде с эхо L9637D, реальные ответы 0B,
устойчивость reconnect при запуске двигателя, LCD/сенсор/PSRAM/Wi-Fi,
потребление и температуры, питание и отсутствие обратного питания через USB.

## Если недоступен реестр компонентов Espressif

В этой среде реестр `components-file.espressif.com` не отвечал. Сборка выполнена
с официальными исходниками LVGL ровно того же релиза:

```bash
git clone https://github.com/lvgl/lvgl.git /tmp/lvgl
git -C /tmp/lvgl checkout 80ca777e37a2b176770726a02e07a6fb79ef0b39
cd firmware
IDF_COMPONENT_MANAGER=0 idf.py -DEXTRA_COMPONENT_DIRS=/tmp/lvgl build
```

Для PowerShell: `$env:IDF_COMPONENT_MANAGER="0"`, затем
`idf.py "-DEXTRA_COMPONENT_DIRS=C:/projects/lvgl" build`.
Это обход недоступного сервиса загрузки; версия библиотеки остаётся 9.6.0.
В `partitions.csv` предусмотрены два app-раздела по 3 МиБ, но OTA-приёмник
пока отсутствует. Пользовательские выборы параметров пяти приборов, тема и
текущий экран сохраняются отдельным worker в NVS после двух секунд без
изменений; одинаковые значения повторно не записываются. Изменение яркости
пока не подключено к драйверу.

В безопасной конфигурации console отключена: `idf.py monitor` не покажет
сообщения приложения. Для UART-логов на изолированном стенде снять JP1,
отключить K-Line в menuconfig и временно выбрать UART0 console с переключателем
Waveshare на USB-UART. Такой диагностический образ не использовать с подключённой
ветвью K-Line. Отладку через native USB/USB Serial-JTAG при использовании GPIO19
для TX_ARM не включать.
