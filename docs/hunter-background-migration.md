# Пользовательские фоны: миграция и восстановление

Ветка `feat/hunter-reference-ui`, экспериментальная функция. Физическая проверка
на ESP32-S3 не выполнена. Обычные однотонный и встроенный фоны не требуют миграции.

## Карта Flash

Все существующие разделы остаются на прежних адресах:
NVS `0x9000/0x5000`, OTA data `0xe000/0x2000`, приложения
`0x10000/0x300000` и `0x310000/0x300000`.
Новые разделы занимают ранее неразмеченные области: `ui_profiles` —
`0x710000/0x10000` (64 KiB NVS для больших профилей), `ui_assets` —
`0x610000/0x100000` на штатной Flash 16 MiB. Старый профиль читается из
прежнего NVS, если новый раздел ещё пуст. Первая подтверждённая запись идёт
в новый NVS атомарно; прежняя копия не удаляется. Без `ui_profiles` остаётся
совместимый режим с бюджетом6144байта packed-профиля; более сложная компоновка
отклоняется с сообщением о необходимости миграции таблицы. Это не отдельная плата.
Четыре ресурса используют по две банки 128 KiB. RGB565 LE, до 240×240,
точный размер payload, версия, CRC и последний записываемый commit header.
При прерывании загрузки остаётся предыдущая целая банка.

## Существующий прибор

OTA обновляет приложение, но не таблицу разделов. На старой таблице прошивка
продолжит работу с прежними настройками; загрузка пользовательского фона вернёт
«Нет раздела ui_assets». Не стирайте Flash и не сбрасывайте NVS для исправления.

Перед изменением таблицы:

1. Экспортировать JSON-профиль через телефон. Сохранить пароль Wi-Fi отдельно.
2. Сохранить всю Flash штатным USB/UART способом для конкретной платы. Для
   esptool v5: `python -m esptool --chip esp32s3 --port COM7 read-flash 0 0x1000000 hunter-backup.bin`.
3. Проверить размер backup 16777216 байт, сохранить SHA256. Сохранить отдельно
   старую `partition-table.bin` из исходной проверенной сборки и backup JSON.
4. Сравнить реальную старую карту с таблицей выше (например,
   `gen_esp32part.py` ESP-IDF). Если адреса отличаются, остановиться: эта миграция
   к другой карте не применима. Не подставлять чужой COM-порт.
5. Собрать/получить проверенную прошивку этой ветки вместе с её таблицей.
   Сначала установить приложение штатным способом/OTA, проверить запуск.
6. Остановить двигатель, отсоединить диагностическую цепь по существующей
   инструкции подключения. Стабильное питание обязательно при записи Flash.
7. Через сервисный порт записать **только** новую таблицу с `ui_assets` и `ui_profiles` по `0x8000`:
   `python -m esptool --chip esp32s3 --port COM7 write-flash 0x8000 partition-table.bin`.
   NVS, otadata, приложения, загрузчик и диагностический жгут не изменяются.
8. Перезагрузить, проверить прежний профиль и пароль, затем загрузить тестовый
   фон. Повторно экспортировать JSON и сверить компоновку и калибровки.

Не использовать `erase-flash` и не загружать объединённый полный образ с
начальным NVS поверх работающего прибора. При сбое сначала вернуть сохранённую
старую таблицу по `0x8000`; старая прошивка просто игнорирует `ui_assets`.
Полный backup — последняя мера восстановления того же прибора. Перед этим
проверить Flash encryption / Secure Boot: для защищённых устройств требуется
их собственная процедура производителя, эта инструкция их не включает.

## Формат загрузки

Телефон проверяет PNG/JPEG/WebP (до 4 MiB, до 4096×4096 и 16M pixels),
центрально кадрирует квадрат и уменьшает до 240×240, затем передаёт только
RGB565 LE. Прибор принимает фиксированный формат, точные размеры и максимум
115200 байт, не декодирует произвольные изображения и не расходует Flash на
оригинал. Есть четыре ресурса, ссылки и затемнение/масштаб — отдельно на экран.
Профиль JSON не содержит бинарных изображений: ресурсы нужно резервировать
отдельно (полный backup Flash). Отсутствующий ресурс показывает однотонный фон.

Миграция описана и проверяется программно по адресам; физический сценарий
потери питания и прошивка таблицы на настоящем устройстве требуют стенда.

Откат таблицы возвращает чтение прежней копии профиля. Настройки, сделанные
после миграции, находятся в новом NVS: перед откатом экспортировать свежий JSON.
Откат на старую прошивку не умеет импортировать JSON v4; для неё нужен сохранённый v3.
