# Калибровки, источники и каталог функций

PortableC-компонент `firmware/components/sources` не зависит отLVGL, Wi-Fi или ESP-IDF. Коэффициенты и выбор источника относятся к данным, а не к конкретному графическому виджету. Код не назначаетGPIO и не отправляет сервисные команды ЭБУ.

## ДМРВ

`bk_calibration_defaults(&c,BK_CAL_MAF)` создаёт **ненастроенный raw-профиль**, а не заводской коэффициент. Для своего датчика пользователь задаёт `configured=true`, имя `profile_name`, метод и диапазоны. При линейном методе применяется **Q=raw×k/divisor+b**. Единица профиляG_S либоKG_H; `bk_calibration_evaluate` переводит их по точному соотношению1g/s=3.6kg/h. Коэффициент применяется после пользовательского выбора без требования подтверждения разработчиком.

Пример пользовательской модели, не характеристика датчика: k=2,divisor=4,b=3,raw=100 →53g/s →190.8kg/h. Диапазоны raw/выхода задаются явно; за пределами расчёт возвращает статус ошибки иNaN, а не правдоподобный ноль. Имя профиля ограничено31байтом плюсNUL. Возврат defaults удаляет применённое преобразование.

МетодTABLE принимает2–8точек `{raw,value}` с строго возрастающимraw. Между точками выполняется кусочно-линейная интерполяция; выход может быть нелинейным и немонотонным, если так задан профиль. За крайними точками экстраполяции/скрытого ограничения нет. Единицы табличныхvalue определяются `unit` профиля. Валидатор проверяет конечность всех чисел, делитель>0, диапазоны, порядок/число точек и совместимость единиц.

## Лямбда

По умолчанию профиль ненастроен, доступны исходные данные. Для расчёта напряжения нужны **пользовательские коэффициенты и явный тип датчика**: NARROWBAND илиWIDEBAND. Подтверждённый заводской масштаб в компонент не зашит. Линейный метод и таблица поддерживаются так же, как уДМРВ; V↔mV переводится по1000. Запрошенный `BK_UNIT_RAW` возвращает именноraw с проверкой входного диапазона, без пересчёта в напряжение.

AFR и lambda-ratio разрешены только при явномWIDEBAND профиле, заданных пользователем единицах/коэффициентах. Вольты широкополосного контроллера не превращаются автоматически вAFR или коэффициентlambda. Несовместимый перевод возвращает `BK_CAL_INVALID_UNIT`. Диагностические сведения сохраняют имя профиля, источник, время, raw и признак `user_calibration`.

## Фактические точки и активность

`bk_signal_activity_*` хранит последние32фактические точки с временем, без усреднения. Окно анализа, epsilon изменения и уровень пересечения задаёт вызывающий код: «заводской порог богатая/бедная смесь» не выдумывается. Возвращаются min/max, число изменений/пересечений и состояния NO_SIGNAL/STATIC/CHANGING/STALE. Наличие колебаний само по себе не доказывает исправность датчика. Частоту точек определяет реальныйK-Line опрос; алгоритм её не повышает интерполяцией. Устаревшие точки не переносятся в свежую статистику.

## Реестр источников

`bk_sources_t` содержит до64пар `metric/source`. Идентификаторы —ASCIIстроки до47символов, например `speed`, `air`, `lambda1`; источник — отдельныйenum: ECU,GPS, физические датчики,DERIVED,USER,MODULE,SIMULATION и др. `bk_sources_register` задаёт приоритет, допустимый диапазон, единицу, срок актуальности и число последовательных подтверждений. Регистрация не делает источник доступным. Для прочих метрик BK_UNIT_NATIVE означает каноническую единицу ID из каталога: например скорость вkm/h; GPS-адаптер обязан сам перевести m/s, а не публиковать другую единицу под тем жеID.

Адаптер публикует `bk_source_sample_t`: value,raw/raw_valid,at_ms,source,unit,confirmed,simulation,user_calibration,profile_name. `confirmed` должен означать семантически проверенный пакет: например валидный кадр ЭБУ, корректныйGPSfix или подтверждённую калибровку датчика. Просто электрическая активность для этого недостаточна. Ошибка диапазона/числа/единицы и отсутствие подтверждения сбрасывают счётчик последовательных подтверждений; после разрыва длиннееfresh_ms подтверждения также набираются заново. Повторное/обратное время не обновляет данные.

`bk_sources_select` возвращает состояние, причину и метаданные. При недоступности value=NaN; raw, источник и время последнего наблюдения сохраняются для диагностики. Будущий timestamp недопустим, устаревшие данные не выдаются свежими. На чистом реестре автоматический режим выбирает первый корректный источник по приоритету. Затем **без `auto_fallback=true` он не переключает выбранный источник молча**, даже если выбранный пропал. Ручной `preferred` закрепляет указанный источник; переход при его пропадании возможен только с явно разрешённымfallback. Настройка автоскрытия/прочерка/постоянного отображения относится к виджету; реестр не создаёт новых экранов автоматически.

Симуляция имеет отдельныйsourceID и адаптер `bk_sources_publish_simulation`; она исключена из рабочего выбора, пока вызывающий код явно не установит `allow_simulation=true`. Название реального датчика при этом не подставляется. Регистрация будущих GPS/TPMS/аналоговых модулей не является реализацией их драйверов. Доступ из нескольких задач следует сериализовать во внешнем слое; сам компонент не выделяет память и не содержитRTOS-lock.

## Каталог

`bk_function_catalog`/`bk_function_find` возвращают статический расширяемый каталог функций из задания: двигатель/датчики, скорость/топливо/поездки, диагностика, обслуживание, дополнительные модули. Для каждой записи есть ID, русское название, единицы, источники, раздел, статус и конкретная причина.

AVAILABLE означает, что соответствующая функция ПО существует, а не что прямо сейчас физический сигнал подтверждён. Её текущие данные проверяет реестр. Неподтверждённые протокольные параметры, отсутствующие датчики и нереализованные вычислители помечены раздельно; скорость, пробег, запас хода и остаток топлива не выдумываются. Время двигателя обозначено как **наблюдаемое время БК**, а не заводские моточасы автомобиля. СбросDTC, вентилятор, бензонасос, форсунки, РХХ, CheckEngine, RCOD/RCOK, коррекцияУОЗ и мотор-тесты имеют **DISABLED**. У каталога нет функции исполнения; он не формирует и не отправляет такие команды.

## Raw из telemetry и проверка

`bk_sample_t` дополнен `raw/raw_valid`; декодер сохраняет исходный целочисленный код иtimestamp вместе с прежним результатом. Существующие PID/масштабы не изменены; уMAF по-прежнему NEEDS_DATA до применения выбранной пользовательской калибровки во внешнем слое. Источникraw не теряется при переводе единиц или отображении.

`tests/test_sources.c` проверяет linear/divisor/offset, обе пары единиц, таблицы и запрет экстраполяции, NaN/Inf/нулевойделитель, семантику narrow/wide, сброс профиля, подтверждение/диапазон/freshness/ручнойвыбор/явныйfallback, исключение симуляции, фактическую активность, полноту/уникальность каталога и сохранениеraw. Standalonegcc с `-Wall -Wextra -Werror -fsanitize=address,undefined` проходит без ESP/LVGL. Сохранение этих конфигураций вNVS/JSON и применение в UI/HTTP выполняет интеграционный слой проекта; аппаратных показаний эти тесты не подтверждают.
