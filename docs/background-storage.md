# Банк пользовательских RGB565-фонов

Компонент `firmware/components/background` хранит4слота, каждый в двух банках128KiB: всего1MiB. БэкендESP находит **существующий** раздел `ui_assets`, адрес0x610000, размер не меньше0x100000. Он не создаёт/не переносит разделы и не меняетNVS/OTA. На устройстве без этого раздела `bk_background_esp_open` возвращаетNO_PARTITION; загрузка также недоступна, существующая прошивка не стирается.

## Формат и ограничения

Пиксели — плотно упакованный RGB565 **little-endian**, безPNG/JPEG/BMP-декодера. Размеры1–240 по каждой оси; длина строго width×height×2, максимум115200байт. Масштабирование и круглыйpreview выполняет внешний слой. Некорректные размеры/длина/slot отклоняются доerase. Хранилище не принимает имена файлов и пути.

Начало банка: `(slot×2+bank)×131072`, slot0–3,bank0–1. Заголовок64байта, целые little-endian:

|Offset|Размер|Значение|
|---:|---:|---|
|0|4|Magic `BKBG`|
|4|2|Версия1|
|6|2|Размер заголовка64|
|8|4|Generation uint32|
|12|4|SlotID|
|16|2|Width|
|18|2|Height|
|20|4|Format1=RGB565_LE|
|24|4|Точная длина пикселей|
|28|4|CRC32 пикселей|
|32|4|CRC32 всего заголовка с обнулённым этим полем|
|36|28|Reserved, нули|

CRC32 — стандартный reflectedCRC-32/ISO-HDLC, полином0xEDB88320, init/xor0xFFFFFFFF; тестовый вектор `123456789` →0xCBF43926. Это проверка целостности, не подпись/аутентификация. Неизвестные version/format, неверные длина/slot/reserved/CRC делают банк недействительным.

## Атомарная запись

1. Проверить оба банка слота вместе сCRC содержимого, выбрать новейший корректныйgeneration.
2. Стереть **только неактивный** банк128KiB.
3. Записать пиксели блоками до512байт; последний блок дополнить0xFF до16байт для flash-write alignment. CRC и metadata считают только точные пиксели.
4. **Последним записать64-байтный заголовок**, затем перепроверить новый банк.

При потере питания до корректного заголовка новый банк игнорируется; предыдущий активный банк не стирается. После полной записи выбирается новыйgeneration. Счётчик поддерживает uint32-wrap; равныеgeneration выбираютbank0 детерминированно. Старый образ остаётся резервом до следующей успешной замены. ОшибкаI/O не считается пустым исправным разделом и не разрешает продолжатьerase вслепую.

## API и интеграция

`bk_background_init` принимает backend read/write/erase, context иsize. `bk_background_load` возвращает metadata и при необходимости пиксели; pixels=NULL выполняет проверку доступности/CRC без копирования. Для маленького буфера возвращаетсяBUFFER_TOO_SMALL вместе с размером корректного изображения. Недоступность не превращается в пустой «валидный» bitmap.

Операции синхронные, безheap и безвнутреннейRTOS-блокировки. Внешний слой должен сериализоватьHTTPзапись/UIзагрузку, сохранять исходныйRAM-буфер неизменным до концаstore и не читатьCRC всего слота на каждом кадре. Загрузить/проверить один раз при смене фона и держать LVGL-совместимый пиксельный буфер отдельно. Firmwaremigration, HTTPавторизация, размеры загружаемого тела и browsercanvas-конверсия относятся к интеграционному слою.

## Проверка

`tests/test_background.c` используетNOR-подобныйfakebackend с правилом записи только1→0 и16-байтным alignment. Проверены остановки наerase, данных и частичномзаголовке вплотьдо63/64байт, сохранение прежнего активного банка, CRC/формат/версия/slot, запредельные размеры/длина, максимальный240×240 bitmap, независимость слотов, wrapgeneration иI/O/no-partition. Standalonegcc `-Wall -Wextra -Werror` +ASan/UBSan:PASS. Эти тесты не означают испытание реальногоflash или всей прошивки при brownout.
