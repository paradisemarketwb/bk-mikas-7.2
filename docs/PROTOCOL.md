# Протокол Микас 7.2 — перенос в ESP32-S3

**Проверенный источник:** старый проект [uaz-mikas-diagnostics](https://github.com/paradisemarketwb/uaz-mikas-diagnostics). В его Windows-версии есть чтение **37 параметров, паспорта и памяти ошибок** через USB KKL. Для конкретного ЭБУ E0000544 данные частично проверялись на машине; некоторые коэффициенты ещё требовали сравнения с OpenDiag. Новый репозиторий публичный — здесь **не дублируем приватные диагностические логи, ключи, персональные файлы**.

## Слои прошивки

1. K-Line PHY: UART ESP32-S3 ↔ согласователь ↔ L9637D ↔ K-Line. Таймауты, инициализация, эхо, пропуски, буферизация — отдельный модуль.
2. Протокол Микас: проверенная последовательность инициализации, кадры запросов/ответов, длины, идентификатор прошивки, проверка корректности данных.
3. Поля: описания ID, размер, знак, формула, единицы, источник, флаг валидности и время обновления.
4. Планировщик: быстро (RPM, температура, напряжение) / средне (впрыск, расход) / редко (паспорт, ошибки). Не перегружать медленную K-Line параллельным опросом всех полей.
5. UI: LVGL на локальном 480×480; обновление индикаторов из последнего валидного снимка, а не прямо внутри UART-обработчика.
6. Wi-Fi SoftAP: телеметрия по HTTP/WebSocket с авторизацией и уникальным паролем устройства; в QR кодировать реальный SSID/пароль.

## Подтверждённые формулы из предыдущего проекта (перепроверить на ЭБУ)

| Поле | Запрос | Формула | Единица |
|---|---|---|---|
| FREQ | профиль Микас | raw×40 | об/мин |
| UACC | профиль Микас | raw/10 | В (по ЭБУ, не независимый вольтметр) |
| TWAT / TAIR | профиль Микас | raw−40 | °C |
| THR | профиль Микас | raw | % |
| UOZ | профиль Микас | signed(raw)/2 | градусы |
| INJ | 61 3F | UInt16LE/125 | мс |
| JQT | 61 40 | UInt16LE/10 | л/ч (оценка ЭБУ) |
| JAIR | 61 21 | UInt16LE/10 **или** /100 | кг/ч, коэффициент требует сверки с OpenDiag |
| RCOD | 61 41 | raw | без подтверждённого коэффициента |
| RCOC/RCOK | 61 42 | raw | без подтверждённого коэффициента |
| Детонация 1–4 | 61 0F | младшие 4 бита | флаги |

**Важно**: это описание декодирования полей, а **не готовые кадры** для непосредственной посылки через UART; подробную обвязку кадра необходимо перенести из проверенного профиля и подтвердить логами. Нельзя показывать отсутствующие данные как `0`. Текущее значение должно иметь `valid`, `age_ms`, `source`.

## Расход топлива

- Без скорости можно показывать **л/ч**, по JQT при корректном ответе ЭБУ.
- При скорости v>0 и JQT в л/ч: мгновенный **л/100 км = 100×JQT/v**, фильтровать малые скорости и деление на ноль; при остановке показывать л/ч.
- Скорость возможна из ЭБУ, если поле поддерживается, или из отдельного GPS-приёмника, который **не входит** в базовую комплектацию.
- Запас хода/остаток топлива нельзя надёжно вывести без измеренного уровня или вручную введённого объёма и накопленного расхода. В UI маркировать оценкой.

## Дальнейшая работа

После базового экрана и электроники портировать формат кадров Python → C++, использовать записанные тестовые ответы для unit-тестов, измерить частоту обновлений и compare-to-OpenDiag. Все сервисные команды (очистка ошибок, исполнительные механизмы, изменение EEPROM) по умолчанию исключены.
