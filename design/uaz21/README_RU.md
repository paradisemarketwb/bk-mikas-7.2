# UAZ Hunter • ресурсы для LVGL

Диаметр 2,1 дюйма = 53,34 мм. Разрешение 480×480 ПРИНЯТО, а не установлено по модели дисплея. Для N×N умножьте координаты и размеры на N/480. Физический диаметр надо сверить по паспорту активной области, не по корпусу.

## Что входит
- 19 базовых иконок, 4 белых варианта для активных кнопок. SVG с прозрачным фоном; PNG 32/48/64 (белые в 48).
- 15 элементов: дуга оборотов, температурная шкала, топливные сегменты, переключатели, плашки, точки, прогресс.
- Исходные прямоугольные фрагменты reference/ для сравнения, включая автомобиль. Их фон сохранён.
- Чертёж PDF на 11 страницах: геометрия и 10 экранов; JSON/CSV с координатами каждого объекта и размерами в мм.
- lvgl_v9/: массивы C 48×48 ARGB8888, объявления и небольшой пример дуги.

## Точность
Иконки вручную восстановлены в векторе по растру, а не извлечены как исходные векторы. Контуры близки к референсу, но попиксельная идентичность не заявляется. Фон, градиенты и шум исходного рисунка в SVG не переносятся. Раскладка адаптирована к 480×480. Исходные фрагменты позволяют сравнить форму.
Шрифты на чертеже — DejaVu Sans, подстановка для проверки габаритов. При выборе шрифта LVGL проверьте реальные метрики; для кириллицы, °, × и λ включите соответствующие глифы. font_px — рекомендуемый номинальный размер, а не высота видимых букв.

## Подключение
1. Для LVGL 9 добавьте uaz_icons.c и uaz_icons.h в сборку. Массивы предназначены для little endian ESP32-S3, stride 192, BGRA bytes = ARGB8888. Используйте lv_image_create и lv_image_set_src(img, &uaz_fuel).
2. Один значок 48×48 требует 9216 байт, все 19 — 175104 байт данных без накладных расходов. По возможности компилируйте только нужные объекты/используйте удаление неиспользуемых секций линковщиком.
3. SVG служат редактируемыми мастер-файлами. Не предполагается, что LVGL умеет читать их без отдельного декодера. PNG требуют включённого PNG декодера и файловой системы либо конвертации в C. Для LVGL 8 конвертируйте PNG официальным конвертером своей версии; массивы v9 напрямую не подключайте.
4. Дуговая шкала — 200° от 170° до 370° по экранной системе (0° вправо, 90° вниз). Центр (240,280), радиус 180, ширина 24. Значение 2450/6000 даёт конец 251,67°. В demo SVG используется тот же коэффициент. Значение скорости показывается отдельно. Шкалу и значение обновляйте из одной модели данных.
5. Температура: линейный диапазон 50…120°C; 87°C = 52,86%. Основной JSON хранит прямоугольники объектов, дополнительные параметры шкал указаны здесь. Указатель и заполнение рисуйте динамически.
6. Топливо: 6 сегментов, активны 4 только как пример. Привязка к реальным литрам зависит от тарировки бака. При отсутствии датчика скрыть либо показать неактивным, не выдавать пример за измерение.
7. QR с иллюстрации не использовать для подключения. Генерировать фактический Wi-Fi QR `WIFI:T:WPA;S:<SSID>;P:<PASSWORD>;;` (экранировать спецсимволы). Сохранить quiet zone 4 модуля и целочисленный размер модуля; выбрать помещающийся QR. В PDF только место под QR.
8. P0110 и P0130 — демонстрационные строки из картинки. Параметры/единицы ДМРВ и лямбды должны поступать из слоя расчёта и пользовательских коэффициентов, а не из этого набора.
9. Масштабирование: дисплей N×N, k=N/480, округлять координаты согласованно. Для прямоугольника в круге проверять все углы: (x−240)²+(y−240)² ≤ 240²; декоративные шкалы могут иметь прозрачные углы за границей. Не накладывайте видимый бордюр поверх активной области.

## Проверка
SVG отрендерены в PNG, прозрачность/размеры проверены автоматически; PDF просмотрен после рендера. На устройстве сборка и шрифты не проверялись. example.c — небольшой пример API, не готовое приложение всех экранов.
